# 반복 도구 큐레이션 워크플로우

**목차** · [입력](#입력) · [권장 실행 형태](#권장-실행-형태) · [cron 기반일 때](#cron-기반일-때)

## 입력

- 현재 사용자 워크플로우
- `USER.md`에 있는 기존 선호
- ClawHub 검색 결과
- OpenHunt 브라우징/검색 결과
- Product Hunt 브라우징/검색/랭킹 결과
- 추후 선택적 추가 소스 (GitHub, Reddit)

## 권장 실행 형태

1. 현재 사용자 작업 테마 파악
   - 자동화
   - 에이전트 워크플로우
   - 지식/위키 워크플로우
   - 리뷰와 요약
   - 채팅 전달과 메시징

2. 집중 쿼리로 소스를 검색하되, 첫 번째 얕은 결과 페이지에서 멈추지 마세요
   - 가능하면 소스 네이티브 목록/랭킹 페이지를 사용
   - 모호한 단일 쿼리 대신 여러 집중 쿼리를 사용
   - 강력한 후보를 너무 일찍 놓치지 않도록 필요하면 더 깊이 페이징

3. 강력한 후보만 선정
   - 기본은 사용자의 "현실 모드" 필터
   - ClawHub에서 최대 5개
   - OpenHunt에서 최대 5개
   - Product Hunt에서 최대 5개
   - 현실 모드의 4개 핵심 축은: 연결성과 확장성, 보안, 수익화 가능성, 특장점
   - 이 4개 중 최소 3개가 높음이고 나머지 하나가 최소 중간일 때 통과
   - 소스에 후보가 너무 적다고 결론짓기 전에, 더 많은 목록 페이지 / 랭킹 페이지 / 추가 집중 검색으로 스캔 폭을 넓히세요

4. 후보당 짧은 이유 한 줄 작성
   - 일반적인 과대광고가 아니라 실제 유용성에 초점

5. 종합 노트 추가
   - 어떤 트렌드나 제품 방향이 중요한가?
   - 사용자의 더 넓은 제품 아이디어에 무엇이 맞는가?

6. 필요하면 간결한 실행 스냅샷 저장
   - `/home/ubuntu/workspace/knowledge-lab/source/openclaw-system/data/tool-curator/YYYY-MM-DD-<source>.md`

## cron 기반일 때

cron 실행 시:
- 짧게 유지하세요
- 반복적인 잡음을 피하세요
- 약한 추천보다 NO_REPLY를 선호하세요
- 정말로 유용한 후보를 찾았을 때만 알리세요
- 사용자가 더 엄격하거나 느슨한 필터를 명시적으로 요청하지 않는 한 기본으로 현실 모드를 사용하세요
- 소스가 부족하게 채워질 때는 포기하기 전에 더 많은 페이징/목록 확장을 하세요
