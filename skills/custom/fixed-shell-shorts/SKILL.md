# Fixed-shell Shorts

## 시각 언어

제작 전 [Structural Calm 디자인 철학](references/structural-calm.md)을 읽고, [참조 캔버스](references/structural-calm-reference.png)를 첫 프레임과 함께 비교한다.

- 셸은 검은 광물성 바탕·따뜻한 본색 활자·얇은 선으로 고정한다. 배경 질감, 그라데이션, 유리 카드, 장식성 그림자는 쓰지 않는다.
- 한 화면에는 한 장면만 둔다. 인물·제품·관계 도식 중 하나가 중앙 창의 70% 이상을 시각적으로 점유하고, 보조 라벨은 주변부에서만 작게 쓴다.
- 중앙 창은 **사진의 밀도**와 **설명 도식의 여백**을 번갈아 배치해 리듬을 만든다. 모든 컷을 같은 검은 카드 또는 같은 흰 도식으로 반복하지 않는다.
- 제목은 한 번에 읽히는 한 문장, 보조 제목은 맥락만, 중앙은 증거만 담당한다. 같은 문장을 세 위치에서 반복하지 않는다.
- 도식은 사각형을 나열하는 대신 객체·관계선·결과의 방향을 명확히 보여준다. 출발·관계·결과 텍스트는 각각 자기 객체/관계 캡슐의 정중앙에 두며, 선 위·객체 밖에 텍스트를 띄우지 않는다. 관계선은 한 방향, 강조색은 한 역할만 가진다.

## 기준 편집 파일

`/home/ubuntu/workspace/video-automation/remotion-map/designs/richard-sapper-carousel/richard-sapper-carousel.pen`은 이 스킬의 **고정 셸 릴스 기준 예시**입니다. 현재 기준 훅은 `좋은 디자인은 / 왜 말을 아낄까?`이며, 새 주제 작업은 이 `.pen`과 같은 폴더의 `index.html`을 함께 복제해 시작합니다. 상·하단 검은 여백, 두 줄 훅, 낮은 중앙 창, 설명컷의 흰 격자 도식은 유지하고 중앙 증거와 훅만 새 주제에 맞게 바꿉니다. `.pen`과 웹뷰는 문구·장면 순서·CTA를 항상 함께 수정합니다.

## 결과 계약

한 편은 하나의 고정 셸과 3~5개의 중앙 콘텐츠 화면으로 만든다.

- 1080×1920, 30fps, MP4.
- 상단의 시리즈명·훅·보조 제목, 하단의 시리즈 표기는 **전 컷에서 픽셀 위치와 문구가 동일**해야 한다.
- 중앙의 테두리 안에서만 인물·제품·설명·마무리 화면이 바뀐다. 전체 프레임, 상·하단 텍스트, 테두리를 줌하거나 전환하지 않는다.
- 기본 흐름은 `인물 → 유튜브 설명컷 → 제품 → 설명컷 → 마무리`다. 주제에 맞지 않는 컷은 바꿀 수 있지만, 화면 하나에는 판단 하나만 둔다.
- 공개 게시·업로드는 별도 승인 없이는 하지 않는다.

## 숏츠 리듬

고정 셸은 브랜딩 장치이고, 시청을 붙잡는 것은 중앙 콘텐츠의 약속과 보상이다. 완성 전 다음 리듬으로 장면을 배치한다.

- **0~1초 — 시각 훅:** 가장 강한 중앙 장면 또는 예상과 다른 한 문장을 첫 프레임부터 보여준다. 로고 인트로, 페이드인, “안녕하세요”로 시작하지 않는다.
- **1~3초 — 약속:** “왜 계속 봐야 하는가”를 하나의 질문·대조·결과로 분명히 한다. 예: `이분도 미니멀리스트` → `기능을 구조 안에 넣었다`.
- **3~12초 — 증거와 전진:** 한 컷에는 하나의 새 정보만 넣고, 매 컷이 직전 질문에 답하면서 다음 질문을 남기게 한다. 인물 → 설명 → 제품 → 원리처럼 사실·물건·해석을 번갈아 배치한다.
- **마지막 2~3초 — 만족과 여운:** 초반의 약속을 한 문장으로 회수하고, 저장·다음 편 시청처럼 행동 하나만 남긴다. 본문과 무관한 CTA를 추가하지 않는다.

고정 셸형에서는 중앙 콘텐츠가 매 2~3초마다 명확히 바뀌어야 한다. 정지 화면에는 자동 푸시인·줌을 넣지 않는다. 설명컷에서 관계선/객체의 절제된 등장만 필요할 때 사용할 수 있다.

## 스토리 비트 계약

스크립트를 쓰기 전, [`viral-short-form`](../../external/viral-short-form/SKILL.md)의 `Hook → Escalation → Payoff → CTA` 구조를 이 고정 셸의 3~5개 중앙 화면으로 번역한다. 사실을 나열하는 영상은 만들지 않는다. 각 화면은 시청자의 이해를 한 단계 바꾸거나, 다음 화면을 볼 이유를 만들어야 한다.

- **약속 (0~3초):** 첫 프레임의 시각 훅과 한 문장 훅이 같은 질문·대조·결과를 약속한다. 초반에 인사·주제 소개·로고를 넣지 않는다.
- **긴장/대조 (중반 초입):** 첫 설명 또는 제품 화면에서 “그런데/그래서”가 성립하는 구체적 장애물·오해·의외성을 제시한다. 장면 둘이 단순히 `그리고`로 이어지면 순서를 바꾸거나 하나를 뺀다.
- **증거와 해소 (중반~후반):** 물건·구조·사례 중 하나를 증거로 보여 약속을 눈에 보이게 갚는다. 가장 강한 결론을 끝까지 숨기지 말고 중반에 작은 보상을 먼저 준다.
- **회수와 한 가지 행동 (마지막):** 첫 훅의 질문을 한 문장으로 닫고, 저장·다음 편 시청처럼 주제와 이어지는 행동 하나만 남긴다. 약속보다 큰 결론이나 근거 없는 교훈은 붙이지 않는다.

각 편마다 렌더 전 아래 비트 시트를 작성한다.

```text
1. 훅의 약속: [처음 3초 안에 답하고 싶은 한 질문]
2. 대조/긴장: [첫 약속을 더 궁금하게 만드는 사실 또는 오해]
3. 증거: [중앙에서 실제로 보여 줄 물건·구조·사례]
4. 해소: [훅에 대한 검증 가능한 답]
5. 행동: [저장/다음 편 등 하나]
```

완성본에서는 모든 열린 질문을 닫고, 어떤 중앙 화면을 빼도 이야기가 그대로라면 그 화면을 삭제하거나 비트를 다시 쓴다. 훅은 보상으로 실제로 입증 가능한 범위만 약속한다.

### 훅 작성 규칙

- 사실을 과장하지 않는다. 충격보다 `의외성 + 구체성 + 즉시 보상`을 우선한다.
- 첫 문장만으로 주제와 보상이 추측 가능해야 한다. 이후에야 이해되는 추상 문장, “오늘은 ~를 소개합니다”는 피한다.
- 훅의 언어와 첫 중앙 화면은 같은 약속을 해야 한다. 인물 훅이면 인물, 제품 훅이면 제품을 첫 프레임에 둔다.
- 훅 후보는 2개 이상 만들고, 한 편에는 하나만 선택한다. 예: 질문형(`이 램프는 왜 선이 없을까?`), 반전형(`미니멀은 빼기가 아니었다`), 결과형(`기능을 구조에 넣은 디자이너`).

## 유튜브 설명컷

중앙 설명컷은 [youtube-explainer-motion 스킬](../youtube-explainer-motion/SKILL.md)의 객체 관계 또는 데이터 차트 규격을 따른다. 특히 오프화이트 48px 격자, `출발 객체 → 관계선 → 결과 객체`, 결론 하나를 유지한다. 한국어 텍스트는 이미지 모델이 아니라 코드/타이포 레이어로 렌더한다.

세로 숏츠에서는 이 설명 그래픽을 중앙 콘텐츠 창에 넣고, 바깥의 고정 셸과 섞지 않는다.

## 제작 순서

1. 고정 문구를 확정하고, 위의 5줄 비트 시트로 훅·대조·증거·해소·행동을 먼저 연결한다. 상단 시리즈명, 훅, 보조 제목, 하단 시리즈 표기는 사용자 요청이 없으면 컷마다 바꾸지 않는다.
2. 훅은 최소 두 가지 각도로 만들고, 첫 3초의 보상과 가장 정확히 맞는 하나를 고른다. 단일 훅을 바로 확정하지 않는다.
3. 중앙 콘텐츠만 별도 이미지/영상으로 준비한다. 정지 이미지에는 카메라 움직임을 넣지 않는다. 설명컷은 객체의 순차 등장이나 관계선 드로잉을 쓸 수 있다.
4. [`scripts/render_fixed_shell_short.py`](scripts/render_fixed_shell_short.py)로 동일한 셸을 합성한다. 중앙 정지 화면은 그대로 유지한다.
5. 시작·중반 보상·설명컷·마지막 프레임을 실제로 확인한다. 상·하단 셸이 이동하지 않고, 중앙만 변하는지 확인한다.
6. 산출물에 이미지 출처 또는 생성 여부를 함께 적는다. 실제 인물 사진의 게시용 사용 조건은 별도로 검토한다.

## 입력 예시

```bash
python3 scripts/render_fixed_shell_short.py \
  --screens portrait.png,explainer-01.png,product.png,explainer-02.png,end.png \
  --top-label '미니멀 모으기 1/100' \
  --hook '이분도 미니멀리스트' \
  --subtitle '리처드 사퍼' \
  --bottom-label '미니멀 모으기 1/100' \
  --output out/short.mp4
```

## 검수

- 전환 전후 프레임을 비교했을 때 상단·하단 문구와 테두리의 좌표가 동일한가?
- 중앙 콘텐츠만 변하고, 중앙·전체 캔버스의 푸시인·줌·흔들림·자막 이동이 없는가?
- 설명컷이 3초 안에 `무엇이 무엇으로 연결되는지` 읽히는가?
- 9:16 안전 영역에서 글자 충돌·잘림이 없는가?
- 첫 1초에 훅의 화면과 문장이 이미 완성되어 있는가? 3초 안에 시청 보상이 보이는가?
- 훅 → 대조 → 증거 → 해소가 `그리고`가 아니라 `그런데/그래서`로 이어지는가? 각 중앙 화면은 다음 화면을 볼 이유를 만드는가?
- 첫 약속이 중반의 증거와 마지막 문장에서 모두 회수되는가? 보상 없이 열린 질문이나 과장된 훅은 없는가?
- 마지막이 초반 약속을 회수하고 행동 하나만 남기는가?

## 게시 후 학습

업로드가 승인된 경우에만 YouTube Studio에서 같은 길이의 최근 숏츠와 비교한다.

- **Viewed vs swiped away:** 첫 프레임·첫 3초 약속을 평가한다.
- **평균 시청 시간·평균 시청 비율:** 전체 리듬과 길이를 평가한다.
- **유지율의 급락(dip):** 해당 컷의 설명량·전환 지연·약속 불일치를 의심한다.
- **재시청/공유 spike:** 명료한 도식·반전·결론을 다음 편 앞쪽에 옮길 후보로 기록한다.

한 번의 성과로 규칙을 고정하지 않는다. 같은 주제·비슷한 길이의 3편 이상에서 반복되는 패턴만 다음 훅/컷 설계에 반영한다.

- [YouTube retention guide](https://support.google.com/youtube/answer/9314415)는 급락·재시청 spike를 다음 편 구조 개선에 쓰도록 안내한다.
