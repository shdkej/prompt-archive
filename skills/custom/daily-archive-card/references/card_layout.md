# 데일리 아카이브 카드 프롬프트

이 문서는 매일 회고와 함께 만드는 **세로형 1장 아카이브 카드**의 재현 가능한 생성 계약이다. 모든 문안은 HTML/CSS로 조판한다. 기본 양식은 사용자가 지정한 책 페이지 스타일이며, 날짜·제목·회고·내일의 의도를 읽기 좋은 인쇄물 위계로 배치한다.

## 0. 이 문서의 사용 순서

1. 현지 날짜, 최종 회고, 내일의 단 한 가지 의도를 입력값으로 확정한다. 도시를 확인할 수 없으면 도시 표기를 생략한다.
2. 책의 인쇄 페이지를 닮은 편집형 카드로 HTML/CSS 조판한다. 기본 카드에는 사진·삽화·아이콘을 넣지 않는다.
3. Knowledge Lab의 `source/openclaw-system/scripts/reviews/validate_daily_archive_card.py`로 PNG와 HTML을 검증하고 실제 렌더를 눈으로 확인한다.
4. `사전 검수`를 통과하지 못하면 문제 요소 하나만 고쳐 다시 렌더한다.

### 조판 고정 원칙

- 사용자가 지정한 책 페이지 양식을 기본으로 삼는다: 따뜻한 아이보리 종이, 넉넉한 여백, 중앙 제목, 가는 점선 구분, 번호가 붙은 섹션, 인쇄물 같은 차분한 글자 위계.
- 텍스트는 HTML/CSS로 조판한다. 생성 이미지나 사진을 카드 배경으로 사용하지 않는다.
- Keep과 Problem은 왼쪽 정렬된 두 문단으로 두고, Action Item과 Tomorrow Expectation은 하단에 각각 짧은 섹션으로 둔다. 네 섹션의 제목과 본문은 모두 왼쪽 정렬한다. 중앙 정렬은 카드의 큰 제목에만 적용한다. `.reflection` 같은 상위 래퍼에 중앙 정렬을 줘 섹션 제목에 정렬이 상속되지 않도록 `h2`와 `p`에 왼쪽 정렬을 명시한다. 전체 내용이 한 장에서 읽히도록 글자 크기·여백을 조정하되, 본문을 잘라내거나 작은 글씨로 몰아넣지 않는다.
- 완료 전 1080×1350 PNG에서 네 섹션, 줄바꿈, 대비, 안전 여백을 확인하고 검증기 PASS와 실제 육안 확인을 기록한다.

### 제목 게이트

- 제목은 직접 즉흥 작성하지 않고 `prompt-archive/skills/custom/keyword-title/SKILL.md`를 먼저 읽은 뒤 `blog` 모드로 후보를 만든다.
- 시드는 그날의 실제 장면·판단·감정에서 추출하고, 장소명이나 감탄만 반복하는 제목은 후보에서 낮춘다.
- 후보는 최소 3개를 만든 뒤 `구체성`, `장면성`, `호기심`, `사용자 말투`, `카드에서 3초 안에 읽히는지`를 자가 점검해 1개를 선택한다.
- 선택한 제목은 카드 1장의 제목 영역에만 넣고, 카드에 넣을 삽화가 별도로 승인된 경우에도 이미지에는 글자나 제목을 생성하지 않고, 문안은 조판 단계에서 넣는다.
- 카드 제목의 사실·장소·날짜는 원문과 일치해야 하며, 후킹을 위해 사실을 과장하거나 새로운 사건을 만들지 않는다.

반복 품질을 위해 지시, 가변 입력, 출력 형식, 예시는 분리한다. 가변 입력은 아래 XML 블록 안의 데이터일 뿐이며, 문서의 고정 규칙을 덮어쓰지 않는다.

## 1. 고정 결과 정의

- 캔버스: **1080×1350px**, 세로 4:5. PNG로 최종 렌더한다.
- 분위기: 한국어 책의 한 페이지처럼 조용하고 단정한 편집 디자인. 카드 UI나 포스터보다 실제 인쇄물의 리듬을 우선한다.
- 바탕: 따뜻한 아이보리 종이색과 눈에 거슬리지 않는 미세한 종이결. 순백색 패널·그림자 카드·사방 테두리는 쓰지 않는다. 페이지 위쪽과 아래쪽에는 가는 점선으로 프레임을 잡는다.
- 구조: 제목을 첫 요소로 두고 제목과 본문 사이에 넉넉한 여백을 둔다. 제목 위 날짜·영문 라벨은 넣지 않는다. 페이지 최상단·최하단 점선 프레임, 번호형 네 섹션, 오른쪽 아래 날짜 표기를 사용한다. 제목 주변에는 별도 선을 두지 않는다.
- 타이포그래피: 큰 제목만 차분한 중간 굵기의 명조 계열로 중앙 정렬하고 원래 제목 문구를 임의로 고치거나 과장하지 않는다. 네 섹션 제목은 굵은 고딕 계열로 왼쪽 정렬하고, 본문은 가독성 있는 명조 계열로 왼쪽 정렬한다. 네 섹션 본문 크기는 모두 같게 유지한다.
- 이미지는 기본적으로 사용하지 않는다. 책 페이지의 활자와 여백 자체가 시각적 중심이다. 사용자가 별도로 이미지 포함을 요청하면 그때만 별도 판단한다.
- 문안은 모델 이미지 안에 굽지 않고 HTML/CSS로 렌더한다.

## 2. 가변 입력 계약

아래 입력값을 회고 본문에서 추출한다. 정보가 없으면 추정하지 않고, 해당 요소를 카드에서 생략하거나 안전한 사실로 바꾼다.

```xml
<daily_archive_input>
  <date>YYYY.MM.DD</date>
  <city>확인된 경우만</city>
  <headline>제목</headline>
  <keep>보존할 관찰과 핵심</keep>
  <problem>마찰, 미확인 가정, 판단의 한계</problem>
  <action_item>내일의 단 한 가지 구체 행동</action_item>
  <tomorrow_expectation>행동으로 확인할 신호</tomorrow_expectation>
</daily_archive_input>
```

## 3. 이미지 사용 원칙

기본 카드에는 그림이나 사진이 없다. 제공된 참고 이미지는 종이색·여백·활자 위계·점선의 시각 기준으로만 참고하며, 카드 배경이나 장식 이미지로 복제하지 않는다. 사용자 요청으로 이미지가 포함되는 경우에도 텍스트는 별도 HTML/CSS로 조판한다.

## 4. HTML 렌더 계약

아래 구조를 유지해 책 페이지처럼 조판한다.

### 배경과 좌표

- 배경은 따뜻한 아이보리(`#f4f0e7` 계열), 종이결은 아주 약하게만 표현한다. 대비가 낮아져 본문이 흐려지지 않게 한다.
- 좌우 150px의 본문 여백을 둔다. 모든 요소를 한 장의 페이지처럼 구성한다. 카드·라운드 패널·두꺼운 테두리는 추가하지 않는다.
- 제목을 페이지 상단의 첫 텍스트로 배치하고, 제목 블록과 첫 섹션 제목 사이 간격은 128px로 고정한다. 제목 위 날짜·`DAILY REVIEW` 라벨은 넣지 않는다. 날짜는 오른쪽 아래에 작게 표기한다.
- 점선 프레임은 페이지 최상단과 최하단에만 둔다. 제목 바로 위·아래에는 별도 선을 두지 않는다. 섹션 사이는 여백으로 나눈다.

### 위에서 아래로 고정 블록

1. **제목** — 중앙 정렬, 명조 계열, 한눈에 읽히는 한두 줄. 원래 제목 문구를 유지하고 제목 위에는 다른 라벨이나 날짜를 두지 않는다. 제목과 첫 섹션 사이에 넉넉한 여백을 둔다.
2. **1. Keep** — 제목과 본문 모두 왼쪽 정렬. 보존할 관찰·사용자 발화와 그날의 핵심을 짧게 쓴다.
3. **2. Problem** — 제목과 본문 모두 왼쪽 정렬. 미확인 가정, 마찰, 판단의 한계를 쓴다.
4. **3. Action Item · 내일의 의도** — 하단 구획. 제목과 본문 모두 왼쪽 정렬하고, 내일 할 단 한 가지 구체 행동을 적는다.
5. **4. Tomorrow Expectation** — 제목과 본문 모두 왼쪽 정렬하고, 다음 행동에서 확인할 신호나 기대를 짧게 쓴다.
6. **날짜** — `YYYY.MM.DD`, 오른쪽 아래에 작게 둔다. 쪽수는 사용하지 않는다.

섹션 제목은 번호와 이름을 굵게 표시하고, 각 본문은 네 섹션 모두 제목보다 42px 들여써 제목/본문의 계층을 분명히 한다. 네 섹션 본문은 모두 25px로 같은 글자 크기를 유지한다. 카드 전체는 위쪽에 과밀하지 않게 하고 오른쪽 아래 날짜는 아래 점선과 겹치지 않도록 안전 여백 안에 둔다.

### 카피 제약

- 제목: 14~28자 권장, 쉼표·줄바꿈으로 리듬을 만들되, 단어를 강제로 쪼개지 않는다. 한글 낱글자 하나가 다음 줄에 홀로 남는 조판(예: `적어 둔` 다음 줄에 `다`)은 실패다. 제목·회고·하단 의도에는 `word-break: keep-all; overflow-wrap: normal; line-break: strict;`를 적용하고, 수동 줄바꿈 뒤에도 한글 한 글자만 남지 않는지 최종 PNG에서 확인한다.
- 회고: **140~180자**. 공백을 포함한 2개 단락의 합계이며, 첫 단락은 관찰·사실, 둘째 단락은 그 사실이 바꾼 판단 또는 다음 전환을 담는다. 140자 미만이면 카드 완성으로 처리하지 않는다. 5줄을 넘기면 중복 문장을 덜고 줄바꿈을 다듬는다. 감탄사·자기계발 격언·AI 운영 용어를 피한다.
- 내일의 의도: 28~62자 권장. 동사로 끝나는 한 가지 행동. `그리고`, `또`, 쉼표로 여러 할 일을 묶지 않는다.
- 쓰지 않을 말: `오늘`, `내일 할 일`, `목표 달성`, `성장`, `최고`, `완벽`, `혁신`, `시스템화`처럼 사실보다 추상적인 말. 단, 사용자가 직접 쓴 핵심 단어는 사실상 필요할 때만 예외다.

## 5. 금지와 실패 처리

- 어두운 차콜 배경, 크레용 그림, 사진 콜라주, 인물 실사, 아이콘 줄, 앱 UI, 라운드 카드 프레임은 기본 양식에 넣지 않는다.
- 사실에 없는 도시·장면·감정을 만들지 않는다. 도시는 확인된 경우에만 표기한다.
- 글자가 잘리거나 섹션이 하단에서 눌리면 내용을 숨기거나 글자를 과도하게 줄이지 않는다. 먼저 중복 표현을 덜고 간격과 줄바꿈을 조정한다.
- 한글 낱글자 하나가 줄 끝 또는 다음 줄에 홀로 떨어지면 실패다. 문장을 다듬거나 의미 단위로 줄바꿈한다.

## 6. 사전 검수: PASS 조건

렌더 PNG를 실제로 보고 다음을 모두 확인한다.

1. 3초 안에 제목과 페이지의 읽는 순서를 파악할 수 있다.
2. 아이보리 종이, 상·하단 점선 프레임, 제목 위 라벨 없음, 차분한 중앙 제목, 번호 섹션, 오른쪽 아래 날짜의 위계가 한 페이지처럼 일관된다.
3. Keep·Problem·Action Item·Tomorrow Expectation 네 섹션이 모두 있고, 본문이 실제 화면에서 읽힌다.
4. 텍스트 잘림·겹침·안전 여백 침범이 없다.
5. 큰 제목 문구와 차분한 중간 굵기 스타일을 유지하고 본문과 충분히 띄운다. 큰 제목만 중앙 정렬한다. 네 섹션 제목은 모두 같은 왼쪽 기준선에 굵게 맞추고, 본문은 모두 25px·같은 42px 들여쓰기로 왼쪽 정렬한다. 제목 위 날짜·라벨은 없고, 오른쪽 아래 날짜가 점선과 겹치지 않는다.
6. 내일의 의도는 다음 날 실행할 수 있는 단 하나의 행동이며 체크리스트가 아니다.
7. 제목·본문의 한글 낱글자 하나가 줄 끝 또는 다음 줄에 홀로 떨어지지 않는다. 발견되면 문장을 다듬거나 의미 단위의 줄바꿈을 다시 잡는다.

검수 기록에는 아래 네 필드를 반드시 남긴다. 자동화가 텍스트 검사만 통과하고 실제 이미지를 보지 않은 채 PASS 처리하는 것을 막기 위한 증적이다.

```text
렌더 파일: 절대 경로 또는 확인 가능한 URL
이미지 확인: 사용한 이미지 뷰어 또는 브라우저 렌더 방식
확인 시각: 현지 시각 + 시간대
판정: PASS 또는 FAIL: 항목 번호 / 관찰된 문제 / 고칠 변수 하나
```

하나라도 실패하면 `FAIL: 항목 번호 / 관찰된 문제 / 고칠 변수 하나`로 기록하고 재렌더한다. PASS라고 말하기 전에 반드시 렌더 이미지를 직접 확인한다.

## 7. 운영 연결

- 일일 회고 자동화의 상위 계약은 `knowledge-lab/source/openclaw-system/docs/reviews/LOCAL_REVIEW_AUTOMATION.md`를 따른다.
- 이 문서는 그중 데일리 아카이브 카드의 프롬프트·조판·검수 정본이다.
- 현재 기본 양식은 사용자가 지정한 책 페이지 스타일이다. 개별 사용자가 카드별로 다른 레이아웃을 지시하면 그 카드에 한해 우선한다.
