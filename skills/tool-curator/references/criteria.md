# 도구 큐레이션 기준

## 1차 필터

다음 차원으로 후보를 점수화하거나 판단하세요:

1. 연결성 & 확장성 (API 개방성 + MCP 호환성 + 플러그인/확장성 + 채팅방 통합 잠재력)
2. 문서 품질 / 문서화 정도
3. 비용 명확성
4. 유지보수성과 배포 표면(deployment surface)
5. 보안 태세 / 신뢰 표면(trust surface)
6. 코드 단순성 / 구현 정갈함
7. 접근성 / 도입 용이성
8. 수익 명확성 / 수익화 가능 표면
9. 차별적 강점 / 두드러진 강점

## 잔디 지표 표시 규칙

큐레이션 잔디 레이어에 기본으로 표시되는 고정 지표:
- 연결성 & 확장성
- 보안 태세 / 신뢰 표면
- 수익 명확성 / 수익화 가능 표면
- 차별적 강점 / 두드러진 강점
- 문서 품질 / 문서화 정도

신뢰할 만한 근거가 있을 때 추가하는 선택 지표:
- 접근성 / 도입 용이성
- 비용 명확성
- 코드 단순성 / 구현 정갈함 (코드 분량과 품질 포함)

## 실용적 해석

사용자는 기술적 개방성을 선호합니다.

이는 다음과 같은 도구에 더 높은 가치를 둔다는 의미입니다:
- API를 깔끔하게 노출하거나 현실적인 MCP/플러그인/채팅 통합 적합성을 가짐
- 에이전트 워크플로우로 감쌀(wrap) 수 있음
- 통합 표면이 전혀 없는 블랙박스 제품이 아님
- API 가격 책정, 고빈도 사용, 인프라 아웃소싱, 워크플로우 락인(lock-in), 강력한 비즈니스 페인 해결 같은 명확한 수익화 쐐기(wedge)를 보여줌
- 단순한 일반 기능 나열이 아니라 기억할 만한 눈에 띄는 강점이 보임

## 전략적 관점

더 깊은 아이디어는 단지 "어떤 도구가 좋은가?"가 아니라:
- 이 도구를 자동으로 발견할 수 있는가?
- 재사용 가능한 기준으로 평가할 수 있는가?
- 사용자의 삶/워크플로우에 빠르게 연결할 수 있는가?
- 이것이 제품화된 큐레이션 + 활성화 레이어가 될 수 있는가?
- 배울 만한 비즈니스 모델이나 수익화 패턴을 보여주는가?

## 특별 처리 규칙

- 보안은 선택적으로 있으면 좋은 것이 아니라 필수 점검 항목입니다.
- 추천되는 모든 항목은 최소 하나의 차별적 강점이나 두드러진 특성을 언급해야 합니다.
- 이 연결성 축을 논할 때는, 더 깊은 분해가 특별히 요청되지 않는 한 API, MCP, 플러그인/확장성, 채팅방 통합을 하나의 결합된 축으로 다루세요.
- 사용자 대면 출력에서는 기술적 포괄 라벨보다 "연결성과 확장성" 같은 평이한 표현을 선호하세요.
