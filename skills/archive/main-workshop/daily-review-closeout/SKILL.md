# Daily Review Closeout

일반적인 하루 기록을 회고 본문·아카이브 카드·회고 캘린더 기록까지 한 작업으로 닫는다. PDCA·가설·Threads 수요검증은 사용자가 명시할 때만 별도 처리한다.

1. 현재 도시·현지 날짜·하루의 사실을 확인한다. 여행 중에는 `hj`의 당일 장소·다음 이동을 보조 근거로 쓰고, 확인되지 않은 감정이나 원인은 만들지 않는다.
   - 날짜·도시·대표 장면 하나가 사실로 확정되면 다음으로 간다.

2. 같은 Slack 스레드에 `Keep → Problem → Action Item → Tomorrow Expectation` 본문을 먼저 보낸다.
   - Keep과 Problem은 각각 `[사실]`과 `[Insight]` 또는 `[Why]`를 분리한다.
   - Action Item은 내일의 단 하나의 실험만 둔다.
   - Tomorrow Expectation은 내일 할 일을 다시 지시하지 않는다. 매 리뷰마다 실제 명언 사이트에서 인용문을 새로 찾아, 원문·저자·출처 페이지를 확인한 명언 하나를 사용한다. `회고` 캘린더의 최근 30일 명언을 확인해 이미 사용한 문구는 다시 고르지 않는다. 가능하면 해당 명언 사이트가 원전(책·연설·인터뷰 등)을 제시한 인용문을 고른다. 명언 본문은 확인된 그대로 옮기고, 번역이 필요하면 번역문임을 표시하며 원문과 출처 링크도 보존한다. 저자나 출처가 불명확하거나 오인용으로 표시된 문구는 쓰지 말고 다른 명언을 찾는다. 명언을 창작하거나 출처를 꾸며내지 않는다.
   - 사용자가 한 일과 자동화 처리, 내부 도구·파일 경로·검증 용어를 본문에 섞지 않는다.

3. 근거와 최종 본문을 `/home/ubuntu/workspace/knowledge-lab/source/openclaw-system/data/daily-reviews/YYYY-MM-DD-review.md`에 저장한다.
   - 같은 날짜 파일이 있으면 보완해 갱신하고 중복 파일을 만들지 않는다.

4. `/home/ubuntu/workspace/prompt-archive/DAILY_ARCHIVE_CARD_PROMPT.md` 전체를 읽은 뒤, 그 계약대로 1080×1350 PNG 한 장을 만든다.
   - 그림은 글자 없는 새 크레용 비트맵 일러스트, 텍스트는 HTML/CSS와 Pretendard로 조판한다.
   - 날짜·도시·제목·서로 역할이 다른 2개 단락의 회고·확인한 명언을 중앙 레일에 둔다. 명언은 인용문과 저자를 함께 표기한다.
   - 최종 PNG를 직접 열어 7개 사전 검수 항목을 확인하고 `validation.txt`에 렌더 파일·뷰어·현지 확인 시각·PASS/FAIL을 남긴다.
   - `validate_daily_archive_card.py FINAL_PNG INDEX_HTML`이 통과해야 다음으로 간다. 스케치나 중간물은 전달하지 않는다.

5. `gog calendar`로 `회고` 캘린더에만 기록한다. 기본 캘린더는 조회·생성·수정하지 않는다.
   - 오늘의 짧은 헤드라인을 `회고` 캘린더에 5분 이벤트로 저장한다.
   - 확인한 명언을 다음 날 21:00–23:59 Asia/Seoul 시간 이벤트로 저장한다. 종일 이벤트로 만들지 않는다. 제목은 `<인용문> — <저자>`로 하고, 설명에는 인용문·저자·명언 사이트의 출처 페이지 URL을 둔다. 제목 앞에 `내일의 한 문장` 같은 고정 문구를 붙이지 않는다. 할 일 목록이나 실행 지시를 캘린더 문구로 만들지 않는다.
   - 생성 전에 `회고` 캘린더에서 같은 날짜·제목을 검색해 중복을 막고, 생성 또는 갱신 뒤 해당 캘린더에서 다시 조회해 확인한다.

6. 카드 검수와 `회고` 캘린더 재확인이 모두 끝난 뒤에만 같은 Slack 스레드에 한 문장으로 마감한다.
   - 하나라도 남았으면 완료라고 말하지 말고, 실패한 항목과 다음 조치만 짧게 알린다.

## 금지

- 회고 본문만 보내고 완료 처리하지 않는다.
- Telegram 리마인더, 자동 Threads, 공개 카드뉴스를 실행하지 않는다.
- 카드가 없거나 캘린더 재확인이 끝나기 전에는 완료 메시지를 보내지 않는다.
